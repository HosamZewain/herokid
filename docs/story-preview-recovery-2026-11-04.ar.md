# استكمال المعاينة بعد استبدال القصة وحذف مراجع صور المنتج

## السلوك

إجراء «استكمال بعد تغيير القصة» يظهر للطلب الموقوف بأمان عند تغير القصة بعد تجهيز معاينة غير معتمدة. يعرض القصة والطفل الحاليين، ويحتفظ بهويات القصص المطابقة ونتائج المنتجات المكتملة. المنتج الذي تغيرت مدخلاته يحتاج اختيارًا صريحًا بين الاحتفاظ بالصورة المعروضة بالمدخلات الحالية أو محاولة إعادة توليد مدفوعة. لا يوجد اختيار افتراضي للمنتج المتغير.

الزر يؤكد بيانات الطلب المعدل، ويلغي انتظار النسخة السابقة وينشئ مسار معاينة جديدًا. لا يسجل موافقة العميل على المعاينة أو دفعًا، ولا يعيد رسالة تأكيد الطلب. المعاينة الجديدة تحتاج موافقة مستقلة؛ الرد على المعاينة السابقة لا يعتمد الجديدة. الإسناد والمدفوعات والنتائج والمحاولات والرسائل السابقة محفوظة.

لا يتجاوز الإجراء التنفيذ الجاري أو النتيجة غير المؤكدة أو الطباعة والشحن أو صفحات Codex السابقة أو موافقة معاينة سابقة. تغيّر البيانات بين الفحص والحفظ يمنع التنفيذ. نطاق السجلات المستبعدة محصور في القصص القديمة المحذوفة منطقيًا والمعروفة للمسار السابق؛ حذف منتج أو سجل آخر لا يُتجاهل.

في «تعديل بيانات المنتج / الصور» يظهر «إزالة الصورة» بجانب كل مرجع حالي، مع «تراجع عن الإزالة» قبل الحفظ. يشترط صلاحية الصور، سبب تعديل، نسخة الصور الحالية والحد الأدنى المطلوب؛ يمكن رفع بدائل في نفس الحفظ. الإزالة تفصل المرجع عن المنتج فقط. لا تحذف كائن S3 أو صورة طفل مشترك أو بيانات محاولة قديمة، ولا تعيد توليد الصور تلقائيًا.

## الهوية والسجل

ترحيل محدد `2026_11_04_230000_scope_process_identity_uniqueness_to_revision` يستبدل تفرّد order_id وattempt_id العام بتفرّد كل منهما داخل run_id، مع فهارس منفصلة لحماية المفاتيح الأجنبية. الإدخال العادي ما زال يمنع أي مطالبة هوية سابقة. وحده المسار الصريح تحت قفل الشراء يستطيع إنشاء طلب هوية جديد أو ربط محاولة ناجحة مطابقة بنسخة جديدة. طلبات ومحاولات الهوية الأصلية تبقى محفوظة. القراءة الإدارية تختار أحدث ربط للمحاولة.

سياق الاستعادة مشفر ويحمل المصدر والقصص المتقاعدة والهويات والمنتجات المختارة. يفحصه العامل وواجهة الإرسال وموافقة الفريق ومسار صفحات كتاب التلوين؛ لا يتسرب رابط تشغيل للعملاء أو RoboDesk. صورة غلاف محفوظة مختارة ليست موافقة عميل.

## النشر والاسترجاع

هذه الوثيقة أُعدّت قبل النشر؛ القسم المؤرخ في runbook هو مرجع النشر الفعلي. يتطلب الترحيل نسخة DB جديدة متحققًا منها خارج الخادم، وقفل نشر ونقطة استرجاع، ثم هذا الترحيل فقط. يحافظ النشر على .env والإعدادات الخاصة وحالة الطوابير والميديا، ويحدّث العمال المتأثرين بعد عملهم الجاري. مولد Codex لا يحتاج إيقافًا أو إعادة تشغيل. إصلاح بطء الموقع مؤجل وغير مضمن.
