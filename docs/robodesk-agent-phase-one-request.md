# رد HeroKid بعد توضيحات RoboDesk — 31 أكتوبر 2026

التوضيحات وصلت، والتنفيذ المحلي اتحدّث بناءً عليها. لم ننشر أو نرسل رسالة أو نغلق محادثة حقيقية.

- لكل رقم عنده طلب منتظر التأكيد، كل تحديث سيقرأ `messagesByPhone` بدون `after` وبـ`limit=50`؛ نفس معدل التحديث الحالي، حوالي ١٠ دقائق مع حدود الطابور. بقية عرض المحادثات يحتفظ بنظامه الحالي.
- نمنع تكرار الرسائل باستخدام `id`، وتسجيل استهلاك رسالة التأكيد يمنع تغيير حالة طلبين بنفس الرسالة. التأكيد المتأخر الذي يسبق الـcursor سيظهر في القراءة الكاملة القادمة.
- نحفظ نفس `channelId` من إيصال الإرسال. لو سجل القالب ظهر بمحادثة مستنتجة مختلفة عن `_id` في الإيصال، الحالة تظهر للمراجعة ولا نغيّر الطلب أو نعيد إرسال القالب.
- نتعامل مع فرق دقة الوقت: رسالة العميل `.000` والقالب بالمللي ثانية. الربط المباشر بمعرّف القالب يسمح بتأكيد نفس الثانية؛ النص المكتوب أو اقتباس رسالة أخرى في نفس ثانية القالب يؤجل للمراجعة لأن ترتيب الحدثين غير مؤكد.
- رسائل `out` لا تؤكد طلبات. `replyTo` لقالب أرسلناه يربط بطلبه؛ أي اقتباس آخر يستخدم آخر قالب سابق داخل نفس المحادثة فقط، وفق الاتفاق السابق.
- المتغير الرابع رقم فقط بعد الخصم وشامل الشحن. اللغة `ar-EG`، دون `procedureId`. نغلق المحادثة المفتوحة ثم نرسل، وإعادة واحدة فقط لخطأ 501 المحدد؛ لا إعادة بعد timeout أو نتيجة غير مؤكدة.

لا يوجد طلب callback أو HMAC أو تعديل خاص بـHeroKid عندكم. لم يعد استكمال شرح الحقول أو الـcursor عائقًا؛ التحقق من أول إرسال فعلي وربط رسالته سيكون في تجربة محددة بعد موافقة المالك، مع الحفاظ على منع الإرسال العام.
