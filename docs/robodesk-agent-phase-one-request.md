# طلب تنفيذ إلى Agent RoboDesk — تأكيد طلب HeroKid فقط

القالب معتمد: `herokid_order_confirmation`، لغة RoboDesk `ar-EG`، Quick Reply «تأكيد الطلب».

مطلوب تنفيذ جانب RoboDesk واختباره ببيانات وهمية، دون إرسال رسالة لعميل حقيقي أو تفعيل الإنتاج:

1. دعم إرسال هذا القالب للعميل حتى لو له محادثة WhatsApp مفتوحة؛ المسار الحالي `start/sendMsg` يعيد 501 في هذه الحالة. حافظ على المحادثة والإجراء الحاليين. لا تغلقها أو تنشئ نسخة بديلة. أرسل عقد الـAPI الفعلي بعد التنفيذ، بما في ذلك استجابة `channelId` و`_id`. إذا استلزم الأمر مسارًا/حقلًا جديدًا، اتفق عليه قبل التفعيل.
2. اعتراض Quick Reply لهذا القالب قبل تحويله إلى AI. النص المكتوب يدويًا ليس تأكيدًا. استخرج `context.id` / `replyTo` من webhook نفسه واحتفظ به؛ لا تعتمد على `messagesByPhone` لأنه لا يعيده.
3. اربط **الرسالة الأصلية** ورقم الطلب الموجود في متغيرها الثاني، وليس متغير `2` الحالي في المحادثة أو آخر طلب لنفس الرقم. حالة طلبين لنفس العميل اختبار إلزامي.
4. نفّذ callback موقّع إلى HeroKid وفق الملف `robodesk-order-confirmation-contract-2026-10-31.md`:
   `POST /api/integrations/robodesk/v1/order-confirmations`
   الحقول: `id` UUID ثابت للمحاولة المنطقية، `order_number`، `template_message_id`، `interaction_id`، `sender_phone` من WhatsApp، `message_id` لضغطة الزر.
5. الحالة عند HeroKid ثابتة `new_confirmed`؛ لا ترسل هدفًا آخر. عند نجاح callback فقط يُسجّل التأكيد. لا تشغّل رفض/دفع/شحن/صور/توليد أو مسار AI بسبب هذه الضغطة.
6. احفظ callback ونتيجته بشكل دائم مع منع التكرار وإعادة نفس UUID عند انقطاع HeroKid. جهّز مكانًا آمنًا للـshared inbound HMAC secret؛ أرسل اسم الإعداد/مسار الملف فقط، ولا ترسل السر في المحادثة.
7. لا تقترح إعادة إرسال القالب عند timeout؛ المسار بلا idempotency، وقد يكون أرسل بالفعل. HeroKid سيحجز النتيجة للمراجعة. أي دعم idempotency جديد يحتاج اختبارًا وعقدًا واضحًا.

ارجع بالتعديلات الفعلية ونتائج اختبارات البيانات الوهمية وعقد إرسال القالب في المحادثة المفتوحة. لا تدّعِ نشر/تفعيل الربط دون دليل وموافقة صاحب المشروع.
