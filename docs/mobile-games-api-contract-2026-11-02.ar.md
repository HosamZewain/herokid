# إعدادات وأحداث الألعاب — عقد الباك إند النهائي v1

تاريخ التنفيذ: 2 نوفمبر 2026. حالة النشر وSHA ونتائج التحقق في قسم الإصدار المقابل في `aws-deployment-runbook.md`، وليس وجود هذا الملف دليل نشر. هذا إصدار باك إند/أدمن فقط؛ ربط الموبايل وإصدار المتاجر خطوة مستقلة. لا تغيير في الطلبات أو الدفع أو الطباعة أو تقدم الأطفال.

## الإدارة

المسار الحالي `/admin/mobile-operations` محفوظ للإعدادات العامة والإصدارات والصيانة والخصومات والخصوصية. التبويبات المضافة:

- `/admin/mobile-operations/overview`: نشاط التطبيق وملخص اللعب.
- `/admin/mobile-operations/games`: الألعاب التسع وصورها وإعداداتها وسجل الاستعادة.
- `/admin/mobile-operations/game-reports`: الفلاتر والمقارنات والرسم اليومي.

القراءة `settings.mobile.view`؛ تعديل الألعاب يحتاج **القراءة والإدارة** `settings.mobile.manage` معًا. لا توسيع لصلاحيات الموظفين. لا تعرض تقارير الألعاب العملاء أو معرفات الأحداث أو الجلسات.

كل حفظ يرسل `config_version` التي فتحت بها الصفحة. تعديلات متزامنة قديمة تُرفض بـ409. سجل الإصدارات يسجل الموظف والوقت، والاستعادة تنشئ إصدارًا جديدًا ولا تمس الإحصائيات. الصور السابقة محفوظة للاستعادة. قواعد المستويات/الثيم/المشهد تزيد `rules_version`، لكن الصورة والعنوان والوصف والاحتفال والصوت لا تزيده. الصور تزيد `card_image.version` منفصلًا. ترتيب اللعبة من1 إلى99؛ عند التعادل يظل ترتيب التعريف الأصلي ثابتًا.

صور الكروت **عامة** وليست صور العملاء: JPEG/PNG/WebP حتى5MiB، كل ضلع128–6000، أقصى16مليون بكسل. يعاد ترميزها WebP (PNG عند غياب encoder)، مع إزالة metadata وتصغير contain حتى1024 دون تكبير. الملفات تحت `public/mobile-games/cards/` برمز عشوائي؛ رابط HTTPS من نطاق الموقع، لا إدخال روابط خارجية. صور الكروت فقط، وليست بديلًا لصور مشاهد اللعب المدمجة.

## GET /api/v1/mobile-app/config

عام؛ لا Bearer/Cookie ولا إنشاء حساب/جلسة زائر. لا تعتمد على endpoint الشراء لاستقبال هذه الإعدادات. `ETag` مع `If-None-Match` يعطي304؛200 يعيد `data` بالشكل التالي (المثال يعرض لعبة واحدة اختصارًا، والرد الفعلي دائمًا9):

```json
{
  "data": {
    "schema_version": 1,
    "config_version": 1,
    "updated_at": "2026-11-02T20:00:00+00:00",
    "games_enabled": true,
    "games_position": 1,
    "games": [{
      "id": "memory",
      "enabled": true,
      "sort_order": 1,
      "title": {"ar": "لعبة الذاكرة", "en": "Memory game"},
      "description": {"ar": "لعبة الذاكرة", "en": "Memory game"},
      "instructions": {"ar": "اقلب الكروت ولاقي كل اتنين شبه بعض", "en": "Flip cards and match each pair."},
      "card_image": {"url": null, "version": 1},
      "rules_version": 1,
      "settings": {
        "enabled_levels": [3, 6, 8], "default_level": 3,
        "themes": ["animals", "colors", "letters"], "default_theme": "animals",
        "celebration_enabled": true, "retry_feedback_enabled": true,
        "sound_enabled": true, "motion_enabled": true
      }
    }]
  }
}
```

| اللعبة | قيم المستويات | إعداد إضافي |
|---|---|---|
| memory |3،6،8 أزواج|themes/default_theme: animals,colors,letters|
| puzzle |4،9،16 **قطعة**|scenes/default_scene: forest,space,ocean|
| differences |1،2،3|—|
| hidden_objects |1،2،3|—|
| patterns |1،2،3|—|
| sequence |1،2،3|—|
| sounds |1،2،3|—|
| problem_solving |1،2،3|—|
| maze |1،2،3|—|

كل الألعاب تحتوي الأربع flags والمستويات والافتراضي. `null` للصورة = الصورة المدمجة. الكلمات/القواعد/الصور تُطبَّق عند المزامنة فقط، مع fallback مدمج وآخر config صالح. لا تُحذف لعبة معطلة من الرد. افحص التفعيل عند الدخول المباشر وبدء الجولة؛ لا تفسد جولة قائمة ولا تمسح التقدم بسبب تعديل صورة/عنوان. لا تُطبّق إعدادات قواعد جديدة على جولة بدأت بإصدار قديم؛ احتفظ بنسخة قواعدها حتى اكتمالها. تقدم اللعبة محلي ولا يُرفع.

`/api/v1/bootstrap` الحالي يظل المصدر الوحيد لإصدارات التطبيق والصيانة والدعم ومحتوى المتجر؛ لا بديل مكرر هنا. النظام المحلي لتقليل الحركة له الأولوية. هذه flags وليست إثبات تنفيذ مؤثرات جديدة أو مؤقت/عقوبة/خسارة في التطبيق.

## POST /api/v1/mobile-app/events

مرسل مستقل غير مربوط بجلسة الشراء، `Content-Type: application/json`. الخادم يتجاهل Authorization وCookie وX-Device-Installation/X-Installation-Id ولا يقرأ Sanctum. لا تُرسل أي بيانات طفل/عميل/طلب/جهاز أو خصائص إضافية.

```json
{
  "schema_version": 1,
  "app_version": "1.1.0",
  "platform": "ios",
  "events": [
    {"id":"7bf0710e-8bfb-4661-980e-0d5e95418a54","name":"game_started","occurred_at":"2026-11-02T16:00:00Z","game_id":"memory","round_id":"6b0dd757-6570-48ac-ae7b-0bdbe9b81697","level":3,"rules_version":1},
    {"id":"9bf0710e-8bfb-4661-980e-0d5e95418a54","name":"game_completed","occurred_at":"2026-11-02T16:01:00Z","game_id":"memory","round_id":"6b0dd757-6570-48ac-ae7b-0bdbe9b81697","level":3,"rules_version":1,"duration_ms":45000,"moves":12}
  ]
}
```

- envelope: schema_version1؛platform `ios|android`؛app_version `major.minor.patch`، مقاطع1–3أرقام وsuffixاختياري `+` أو`-` ثم1–16حرف/رقم/نقطة/شرطة، إجمالي≤32. لا أسماء إصدار حرة.
- events: قائمة1–50، body≤65536byte. idUUID ضروري لكل عنصر؛ round_idUUID للبدء/الإكمال. أنشئ UUID عشوائيًا لا مشتقًا من حساب/جهاز. ثبّت بيانات الحدث والـUUID في إعادة المحاولة، لا تحدث توقيته.
- occurred_at: ISO8601 معtimezone، دقة≤3كسور؛ الماضي≤7أيام والمستقبل≤5دقائق. وقت الاستقبال يسجل منفصلًا UTC.
- app_opened: id/name/occurred_at فقط (+session_idاختياري).
- screen_viewed: أضف screen من `home|games|library|catalog|settings` فقط. لاURLs أوعنوان قصة/بحث.
- game_opened: أضفgame_id فقط، بلا round/level/rules.
- game_started / game_completed: game_id +round_id +level +rules_version. الاستكمال قبل البدء مقبول. اللعبة/المستوى/القواعد والمنصة/إصدار التطبيق ثابتة للجولة حتى أثناء ترقية التطبيق؛ اجمع دفعة منفصلة لأحداث إصدار قديم محفوظة أوفلاين.
- game_completed وحده يقبلduration_ms اختياري1–14400000 وmovesاختياري1–100000. الوقت الفعلي يستبعد الخلفية. القيمة الغائبة تعني غير مقاسة، لاصفر. مدة تتجاوز الزمن بين البدء والإكمال+5ثوانٍ لا تدخل المتوسط. توقيت إكمال سابق للبدء لا يدخل مجموعة الجولات المكتملة المطابقة.
- session_id اختياريUUID مؤقت: أنشئه لكل جلسة مقدمة جديدة، ودوّره بعد30دقيقة خلفية أو24ساعة كحد أقصى؛ لا تحفظه كتثبيت دائم. الخادم يرفض مدى جلسة>24ساعة أو اختلاف المنصة/الإصدار. ترتبط أرقام الجلسات بيوم أول حدث عند وصول أحداث أقدم.
- البدء والإكمال مرة واحدة لكلround_id حتى لو وصلUUIDحدث جديد. نفسidمعpayloadمختلف مرفوض. replayفعلي=roundUUIDجديد. تظل القواعد الأقدم مقبولة للتزامن المتأخر؛ المستقبل غير المعروف مرفوض. eventsليست آلية منعغش أو حساب مكافآت مالية.

نجاح/رفض جزئي HTTP202:

```json
{"data":{"accepted_ids":["7bf0710e-8bfb-4661-980e-0d5e95418a54"],"duplicate_ids":[],"rejected":[{"id":"9bf0710e-8bfb-4661-980e-0d5e95418a54","code":"event_outside_window","retryable":false}]}}
```

أكواد نهائية: `unknown_field`, `invalid_event`, `invalid_fields_for_event`, `unsupported_level`, `unsupported_rules_version`, `event_outside_window`, `event_id_conflict`, `round_conflict`, `session_conflict`. الوحيد المؤقت داخل202 هو `temporarily_unavailable` مع retryable=true. امسح المقبول والمكرر والمرفوض نهائيًا من الطابور؛ أعد المؤقت فقط بنفس UUID مع backoff وjitter. عند timeout أو فشل الشبكة، أعد نفس الدفعة بأمان.

HTTP422 `{"error":{"code":"schema_invalid"}}` للغلاف أو UUID مفقود/غير صالح؛ 415=json_required؛ 413=payload_too_large. HTTP429 مع Retry-After و5xx قابلان للمحاولة المتأخرة، دون حلقة سريعة. الحد30 طلب أحداث/دقيقة و120config/دقيقة للمصدر، وسقف3000 طلب/دقيقة لكل endpoint؛ cache موجود وHMAC لعنوانIP يتغير يوميًا، بلاIP في الجداول أو مفتاح ثابت داخل التطبيق. مشاركة شبكة واحدة قد تؤخر المزامنة، ولا يجب أن توقف اللعب. لا طابور جديد أو خدمةAWS جديدة.

## تعريف التقارير والتخزين

التخزين UTC، والتجميع بأيام Africa/Cairo مع DST. الفلاتر: from/to حتى366 يومًا شاملًا، platform/app_version/game_id/level. فتح اللعبة ليس له مستوى ويظهر في صف «بدون جولة»؛ عند فلتر مستوى لا يمكن نسبة فتح الصفحة إليه.

البدء والإكمال الخام يُعرضان حسب يوم حدوثهما. `matched_completed` ينسب ليوم البدء بعد مطابقة الجولة؛ لذا النسبة لا تقسم إكمالات يوم مختلف على بدايات اليوم. المتوسطات من نفس مجموعة البدايات، ومعها عدد العينات الصحيحة. غياب القياس يعني «غير متاح». نشاط التطبيق والجلسات مستقل عن فلتر اللعبة والمستوى وموسوم بذلك. آخر received_at وقت استقبال، وليس آخر لعب. لا استنتاج لعدد الأطفال أو المستخدمين أو التنزيلات. العدادات لا تُسترجع من أرقام موبايل محلية قديمة.

Migration إضافي فقط: `2026_11_02_210000_create_mobile_game_settings_and_metrics.php` ينشئ configs/config_versions/events/rounds/sessions/daily؛ لا يمس جداول الطلبات. مفاتيح UUID فريدة، وصف الجولة مقفول داخل transaction، وتجميع يومي بمفتاح فريد وزيادات ذرية، مع إعادة deadlock حتى5 محاولات. جداول الأحداث بلا user_id أو installation_id أو IP أو headers. سجل إدارة الإعدادات وحده يسجل الموظف بآلية الأدمن القائمة.

الاحتفاظ الخام افتراضي90 يومًا، قابل للضبط بين30 و365. المجاميع اليومية وسجل الإعدادات محفوظان. `php artisan mobile-games:retention` **dry-run فقط**. الحذف يتطلب تصريحًا منفصلًا وتشغيل `--execute --confirm-cutoff=YYYY-MM-DD` بعد مراجعة cutoff بتوقيتUTC؛ يحذف فقط الخام الذي آخر received_at له قبل الحد، ويحفظ المجاميع. لا جدولة حذف مضافة ولا تنظيف إنتاجي بهذا الإصدار. معرفات انتهت مدة الاحتفاظ بها لا يبقى لها دليل dedupe؛ لذلك يجب الالتزام بنافذة7 أيام وعدم تحويل حدث قديم إلى توقيت جديد.

## اختبارات وتسليم الموبايل

اختبارات Feature معزولة على SQLite وMySQL وPHP8.3، مع منع HTTP stray requests. اختبار حقيقي بثماني عمليات متزامنة في MySQL داخل شبكةDocker internal بلا أسرار إنتاج: نفس الأحداث، وترتيب معكوس، ومعرفات أحداث جديدة لنفس الجولة؛ نتيجته جولة مطابقة واحدة. التفاصيل والأرقام النهائية في runbook. لا أحداث وهمية على الإنتاج.

المطلوب من Agent الموبايل:

1. تثبيت المعرفات والمستويات، وربط config وETag وfallback، مع الاحتفاظ بآخر إعداد صالح.
2. مرسل anonymous مستقل، وطابور offline محدود7 أيام، وتطبيق تعريف الجلسة وقواعد الجولة المحفوظة كما سبق.
3. تطبيق flags مع أولوية reduce-motion؛ حفظ التقدم محليًا. لا نقل لمحتوى اللعب أو حساب طفل إلى هذا المسار.
4. اختبار إعادة التشغيل والخلفية والنقر المكرر والرفض الجزئي و429 والأوفلاين قبل نشر المتاجر.

ملاحظة منفصلة: مسار المكتبة الخاصة `/api/v1/library/books` وعقد `account-owner-or-verified-phone-v1` ليسا ضمن هذا التعديل؛ لا تنشر الكود المحلي المتسخ المتعلق به ضمن الألعاب. حالة الفحص الإنتاجي موثقة في runbook. مسودة الإفصاح في `mobile-privacy-disclosure-draft-2026-11-02.ar.md` تحتاج مراجعة المالك قبل المتاجر.
