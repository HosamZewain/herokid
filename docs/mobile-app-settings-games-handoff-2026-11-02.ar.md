# طلب الباك إند: إعدادات تطبيق الموبايل والألعاب

عاوز صفحة في الأدمن باسم **إعدادات تطبيق الموبايل**، أتحكم منها في الألعاب وصور كروتها وإعداداتها، وأشوف إحصائيات استخدام التطبيق والألعاب. القياس يكون على سيرفر HeroKid، مش Firebase، ومش مطلوب شاشة إحصائيات لولي الأمر داخل التطبيق.

هذا عقد ربط مقترح للتنفيذ، وليس وصفًا لمسارات منشورة بالفعل. ربط واجهة الموبايل سيحتاج تحديثًا مستقلًا بعد تثبيت العقد ونشره. لا تغيّر تسجيل الدخول أو الطلبات أو الدفع أو الموافقات أو الطباعة.

## 1. ابدأ بالموجود، ولا تعمل لوحة مكررة

في الكود المحلي توجد صفحة `/admin/mobile-operations` في `MobileOperationsController`، وصلاحيات `settings.mobile.view` و`settings.mobile.manage`، ومسار `POST /api/v1/analytics/events`. راجع النسخة الفعلية على AWS أولًا؛ وجود الكود محليًا ليس إثبات نشر.

طوّر الصفحة الحالية أو أنشئ واجهة مرتبطة بها باسم «إعدادات تطبيق الموبايل»، مع الحفاظ على الإعدادات وأكواد الخصم والخصوصية الموجودة. لا توسّع صلاحيات الموظفين أو تعرض بيانات العملاء في تبويب إحصائيات الألعاب.

تبويبات الصفحة:

- نظرة عامة: فتح التطبيق، الجلسات، فتح صفحات الألعاب، بدء الجولات وإكمالها.
- الألعاب: قائمة الألعاب التسع والتحكم فيها.
- تقارير الألعاب: جدول ورسوم يومية ومقارنة الألعاب والمستويات.
- إعدادات عامة: تشغيل قسم الألعاب، وترتيبه، والنسخة الأخيرة والدعم؛ استخدم إعدادات الإصدارات والصيانة الحالية ولا تنشئ بديلًا متعارضًا.

## 2. الألعاب الموجودة فعلًا في التطبيق

ثبّت هذه المعرّفات؛ لا تستخدم العنوان العربي كمفتاح ولا تسمح بإضافة لعبة غير مدعومة بمجرد إدخال اسم جديد.

| id | الاسم | قيم المستوى المدعومة حاليًا |
| --- | --- | --- |
| memory | لعبة الذاكرة | 3، 6، 8 أزواج |
| puzzle | البازل | 4، 9، 16 قطعة، وليست أبعاد الشبكة |
| differences | اكتشف الاختلافات | 1، 2، 3 |
| hidden_objects | الحاجة المستخبية | 1، 2، 3 |
| patterns | كمّل النمط | 1، 2، 3 |
| sequence | رتّب الحكاية | 1، 2، 3 |
| sounds | محقق الأصوات | 1، 2، 3 |
| problem_solving | حل المشكلة | 1، 2، 3 |
| maze | متاهة الحكاية | 1، 2، 3 |

لكل لعبة:

- تفعيل/إيقاف، وترتيب العرض.
- اسم ووصف قصير وتعليمات بالعربي والإنجليزي، بحدود طول واضحة.
- رفع/استبدال صورة كارت اللعبة، ومعاينة شكلها قبل الحفظ. المقصود أولًا صورة اللعبة في قائمة الألعاب، وليس تغيير كل كروت الذاكرة أو محتوى المشاهد تلقائيًا.
- اختيار المستويات المفعّلة والمستوى الافتراضي منها؛ التحقق من القيم حسب اللعبة.
- إعدادات مناسبة للعبة فقط: مثل ثيم الذاكرة `animals|colors|letters`، ومشاهد البازل المدمجة `forest|space|ocean`.
- إعدادات عرض الاحتفال وتشجيع إعادة المحاولة والصوت/الحركة، ضمن ما ستدعمه نسخة الموبايل؛ النظام المحلي لتقليل الحركة له الأولوية.
- تاريخ آخر تعديل واسم موظف التعديل وسجل تغييرات، مع إمكانية استعادة إعدادات سابقة بدون حذف تاريخ الإحصائيات.

لا ترسل JavaScript أو HTML أو routes أو URLs تنفيذية من الأدمن للتطبيق. إعدادات typed ومحددة، وليس JSON مفتوحًا بلا تحقق. إضافة لعبة جديدة أو نوع محتوى جديد غير مدعوم تحتاج تحديث التطبيق.

صور الكروت عامة مثل صور الكتالوج: رفع آمن إلى `public` وفق قواعد المشروع، JPEG/PNG/WebP فقط مع فحص المحتوى والحجم وإزالة metadata وإعادة الترميز. لا تستخدم ملفات أو صور العملاء أو مساحة `s3_private` للطلبات. صورة مربعة 1024×1024 مناسبة، مع معاينة وعدم تشويه النسبة.

## 3. عقد إعدادات عام للتطبيق — مقترح جديد

`GET /api/v1/mobile-app/config` بدون تسجيل دخول أو جلسة زائر.

```json
{
  "data": {
    "schema_version": 1,
    "config_version": 1,
    "updated_at": "2026-11-02T16:00:00Z",
    "games_enabled": true,
    "games": [
      {
        "id": "memory",
        "enabled": true,
        "sort_order": 1,
        "title": {"ar": "لعبة الذاكرة", "en": "Memory game"},
        "description": {"ar": "حيوانات وألوان وحروف", "en": "Animals, colors and letters"},
        "instructions": {"ar": "اقلب الكروت ولاقي كل اتنين شبه بعض", "en": "Flip cards and find the matching pairs"},
        "card_image": {"url": null, "version": 1},
        "rules_version": 1,
        "settings": {
          "enabled_levels": [3, 6, 8],
          "default_level": 3,
          "themes": ["animals", "colors", "letters"],
          "default_theme": "animals",
          "celebration_enabled": true,
          "retry_feedback_enabled": true
        }
      }
    ]
  }
}
```

أرجع الألعاب التسع، بما فيها المعطّلة بـ`enabled:false`. الصورة `null` تعني الصورة المدمجة في التطبيق. لو رابط موجود يرجع HTTPS على نطاق/تخزين HeroKid المسموح، مع إصدار للصورة عند تغييرها.

ادعم ETag/304 وتحديثًا ذرّيًا لـ`config_version`. لا ترجع بيانات موظفين أو إحصائيات أو معلومات عملاء في هذا المسار العام.

الموبايل سيقرأ الإعدادات عند التشغيل/العودة للمقدمة، ويحتفظ بآخر إعداد صالح، مع الصور والإعدادات المدمجة كـfallback عند أول تشغيل بلا إنترنت. التغيير يسري عند المزامنة؛ لا تعد بإيقاف فوري على جهاز أوفلاين. التعطيل يمنع بدء جولة جديدة بعد التحديث ولا يفسد جولة جارية. افحص التفعيل أيضًا في الدخول المباشر للعبة، مش إخفاء الكارت فقط.

افصل إصدار الصورة عن `rules_version`: تغيير صورة الكارت أو عنوان اللعبة لا يمسح تقدم اللاعب. تغيير قواعد مؤثرة على حفظ الجولة يحتاج إصدار قواعد جديد وسياسة توافق موثّقة.

## 4. إحصائيات مجهولة على HeroKid — عقد مقترح جديد

المسار الحالي `analytics/events` يحفظ `user_id` و`X-Device-Installation`. لا تستخدمه كما هو لجمع لعب الأطفال. أضف مسارًا مخصصًا مثل:

`POST /api/v1/mobile-app/events`

يعمل كضيف بدون حساب، بدون إنشاء جلسة زائر، وبدون Bearer أو معرّف تثبيت دائم. لا تربط هذا النوع من الأحداث بحساب حتى لو وُجدت headers من عميل قديم. في الموبايل سنستخدم مرسلًا مستقلًا لا يحقن بيانات جلسة الشراء.

الأحداث المسموحة فقط في المرحلة الأولى:

- `app_opened`: فتح التطبيق/عودة مؤهلة من الخلفية؛ ليس كل render أو إذن نظام.
- `screen_viewed`: اسم شاشة ثابت من allowlist، بدون اسم قصة أو slug أو URL أو نص بحث.
- `game_opened`: دخول صفحة اللعبة، حتى لو لم يبدأ اللاعب.
- `game_started`: ضغط بدء جولة فعلية؛ replay جولة جديدة، وفتح التعليمات أو ملء الشاشة ليس جولة.
- `game_completed`: إكمال الجولة مرة واحدة فقط.

```json
{
  "schema_version": 1,
  "app_version": "1.1.0",
  "platform": "ios",
  "events": [
    {
      "id": "7bf0710e-8bfb-4661-980e-0d5e95418a54",
      "name": "game_started",
      "occurred_at": "2026-11-02T16:00:00Z",
      "game_id": "memory",
      "round_id": "6b0dd757-6570-48ac-ae7b-0bdbe9b81697",
      "level": 3,
      "rules_version": 1
    }
  ]
}
```

لحدث الإكمال يمكن إضافة `moves` و`duration_ms` بأرقام وحدود تحقق واضحة، مع استبعاد الوقت في الخلفية من مدة اللعب. `game_opened` لا يتطلب `round_id`، و`app_opened` لا يتطلب `game_id`.

استخدم UUID عشوائيًا للحدث وUUID للجولة، لا child ID ولا اسم/رقم/صورة ولا account ID أو installation UUID أو advertising ID أو بصمة جهاز. لو احتجنا جلسة، UUID مؤقت لجلسة التطبيق فقط، مع تعريف انتهاء الجلسة بوضوح، وليس هوية دائمة للطفل. لا تحفظ IP أو headers في جدول التحليلات؛ انتبه أيضًا لسجلات الأخطاء والطلبات ولا تسجل payloads أو أسرارًا. السجلات الأمنية الأساسية لها سياسة مستقلة، وليست أداة لتتبع الأطفال.

متطلبات الاستقبال:

- batch بحد أقصى 50؛ UUID فريد في قاعدة البيانات، وإعادة إرسال نفس الحدث لا تزوّد العداد.
- منع تكرار البدء/الإكمال لنفس `round_id`، والتحقق من توافق game/level/rules ونوع الحدث.
- دعم وصول الإكمال قبل البدء أو وصول أحداث أوفلاين بترتيب مختلف، بدون رفضها نهائيًا أو مضاعفة الإحصائيات؛ جولات الإكمال بلا بداية مؤكدة لا تدخل نسبة الإكمال حتى التسوية.
- أسماء وحقول allowlist وحدود للحجم والتوقيت ومدة التأخير المقبولة، مع clock-skew معقول؛ لا تقبل خصائص حرة.
- rate limiting وحماية abuse بدون مفتاح سرّي ثابت داخل التطبيق، وبدون reCAPTCHA/تسجيل دخول يعطّل اللعب.
- النتيجة `202` مثل `data.accepted_ids` و`data.duplicate_ids`، وأي رفض جزئي بـID وكود آمن لكي يعيد العميل الأحداث المؤقتة فقط. أخطاء schema ثابتة تكون موثّقة بـ422.
- Redis/cache/queues الموجودة فقط عند الحاجة؛ صفر موارد AWS جديدة أو خدمات تحليل مدفوعة.

## 5. تقارير الأدمن وتعريف الأرقام

فلاتر الفترة، iOS/Android، إصدار التطبيق، اللعبة والمستوى. واجهة التواريخ بتوقيت `Africa/Cairo`، والتخزين UTC، بدون افتراض offset ثابت.

لكل لعبة: فتح الصفحة، الجولات التي بدأت، الجولات المكتملة، نسبة الإكمال، ومتوسط مدة الجولات المكتملة ومحاولاتها عند توفر قياس صحيح. اعرض نسبة الإكمال من نفس مجموعة الجولات التي بدأت خلال الفترة، وليس قسمة أحداث مكتملة من فترة مختلفة على بدايات اليوم. عالج المزامنة المتأخرة بدون مضاعفة المجاميع.

اعرض الرسم اليومي، الأكثر لعبًا، وآخر تحديث واستقبال. ميّز وقت اللعب `occurred_at` من وقت وصوله `received_at`. لا تسمّ عدد الأحداث أو الجلسات «عدد الأطفال» أو «المستخدمين الفريدين» أو «التحميلات». الإحصائيات تبدأ من نسخة الموبايل التي تدعم الإرسال؛ لا تخترع أرقامًا للنسخ القديمة أو تحول العدادات المحلية القديمة إلى أحداث مكررة.

سياسة احتفاظ موثّقة: أحداث خام لفترة محدودة قابلة للضبط، ثم مجاميع يومية. أي تنظيف لبيانات موجودة أو جدولة حذف فعلية يتطلب مراجعة النطاق والموافقة المناسبة، وليس حذفًا أثناء اختبار الميزة.

## 6. التقدم والاحتفالات — تمهيد للتطبيق

في المرحلة الأولى، تقدم كل لعبة يبقى محليًا على الجهاز، من غير حساب طفل أو ربطه بطلب. هنحتاج على الأقل game_id وlevel وrules_version وحالة الجولة؛ تغييرات صورة الكارت لا تمسحه.

التطبيق سيعرض تقدم الجولة واحتفالًا هادئًا عند الإكمال وتشجيعًا لطيفًا عند الخطأ. الألعاب الحالية ليس فيها خسارة نهائية أو مؤقّت؛ الإجابة الغلط ليست `game_failed`. لا تضف مؤقّتًا/عقوبة/إعادة تعيين أو تدّعي أن تأثيرات جديدة جاهزة لمجرد إضافة إعداداتها في الأدمن. مزامنة تقدم عبر الأجهزة أو رفع محتوى اللعب نفسه تحتاج عقدًا مستقلًا لاحقًا.

## 7. اختبارات وتسليم الباك إند

- اختبارات معزولة لتعديل الاسم والصورة والترتيب والتفعيل والإعدادات، وحماية الصلاحيات وسجل التغيير.
- التحقق من schema/ETag/image version ورفض إعدادات ومحتوى غير مدعوم أو ملفات غير آمنة.
- استقبال أحداث الضيف، منع التكرار المتزامن، أحداث أوفلاين وترتيب معكوس، تقارير الفترات والمستويات والتوقيت ونسبة الإكمال.
- تأكيد أن أحداث اللعب لا ترتبط بالحساب/التثبيت حتى مع وجود Authorization أو X-Device-Installation في الطلب.
- لا اختبارات أو طلبات ألعاب وهمية على production؛ fixtures محلية، وبيانات الاختبار لا تدخل تقارير العملاء.
- لا تغيير checkout أو الدفع أو الطباعة أو بيانات العملاء، ولا خدمات أو مصاريف جديدة.
- قبل أي نشر اتبع `docs/aws-deployment-runbook.md` وحدد نطاقه؛ الإنتاج AWS، وHostinger مصدر استعادة مجمّد. احتفظ بكل التعديلات الأخرى، ولا تنشر الـworktree المتسخ كحزمة واحدة.

سلّمني العقد النهائي وأمثلة JSON، migrations والصلاحيات، نتائج الاختبارات، وما الذي تم نشره فعلًا مع SHA وتاريخ التحقق. بعد ذلك سنربط الموبايل ونختبر رحلة حقيقية منفصلة. نجاح الباك إند وحده لا يعني أن صور الألعاب/الإعدادات أو الإحصائيات اتربطت في التطبيق.

## ملاحظتان منفصلتان لتجهيز إصدار المتاجر

- في فحص القراءة الإنتاجي بتاريخ 2 نوفمبر 2026 نجح دخول حساب المراجعة بـ200، لكن `GET /api/v1/library/books` رجع404، بينما المكتبة العامة والكتالوج رجعا200. إعادة التحقق مطلوبة؛ لا تعتبر وجود مسار المكتبة الخاصة محليًا إثبات نشره. المطلوب عقد `account-owner-or-verified-phone-v1` وملكية الطلب، وليس إتاحة ملفات الطلبات كروابط عامة أو الاكتفاء بتطابق رقم موبايل غير موثّق.
- جهّز تحديث بيان الخصوصية لوصف القياس الداخلي المجهول والصور المعالجة عبر OpenAI API والإشعارات، بدون الادعاء بتشغيل Firebase Analytics. راجع إقرارات المتاجر مع المالك قبل تقديمها؛ فصل تحليلات الألعاب لا يلغي بيانات الحساب/الشحن أو FCM/APNs اللازمة لخدماتها.
