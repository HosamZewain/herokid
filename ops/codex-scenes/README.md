# Codex story and coloring-book queue

## Coloring-book pages / protocol 5

Protocol5 supports 1–1000 portrait interior pages. Each manifest and output includes exact order_item_id and production_kind=coloring_book, plus existing run/order/approved-cover checksum correlation. The same bounded two-slot worker pool and per-page attempt ledger apply. No API fallback, whole-book retry or replacement of accepted pages. Laravel requires a current approved combined-preview manifest and positive recorded payment before admission, and verifies private S3 attachment ownership on each page. Old protocols retain their original behavior. See [book and review contract](../../docs/automation/coloring-book-and-preview-contract.md). New flags remain off pending template/RoboDesk readiness.

## Independent scenes / protocol 4 — prepared 2 November 2026

New runs use a durable scene-attempt ledger. Each scene gets at most **two CLI invocations**, and only a definite local PNG/dimension/size/duplicate failure permits the second attempt. No whole-story automatic restart. Accepted scenes are never regenerated. A refusal reported by the CLI, missing output, nonzero result or killed timeout gets one attempt and is left for review; the worker continues the other scene numbers. No prompt substitution, safety bypass, API fallback, or assumed zero-cost failure. A process/host interruption still requires operator reconciliation and is never automatically replayed.

Every request is reserved in atomic status before launch; completed outcomes and private per-attempt logs/rejected bytes are preserved. Laravel imports only images whose atomic scene state says succeeded, verifies their story/reference/SHA and private S3 readback, and records attempt start/result as Automation. The next scene uses the nearest earlier accepted scene for continuity plus the approved identity. Explicit 1536x1024 landscape instruction remains; local minimum-size validation is not visual/print certification.

At the end, 13 verified scenes mean `ready_preview`. Otherwise the run is `needs_manual`, the story becomes **`pending_team_review` / بانتظار مراجعة الفريق**, its active reservation is released and the UI lists exact missing numbers, attempts and reasons. Automatic enrollment excludes prior runs, preventing a new whole-story loop. Ownership may remain Automation when another sibling story in the checkout is genuinely still running. Staff completes only missing scenes. Partial stories do not enter the completed-story timing average.

Legacy protocol 1–3 remains readable with its existing stop semantics; never upgrade an in-flight manifest. `codex-scenes:resume-quality` creates a fresh audited UUID retaining accepted S3 bytes. For an operator-reviewed **legacy prefix** followed by a content refusal, explicit `--skip-content-scene=N` skips that exact next scene without retry, generates later scenes, and hands the remaining gap to the team. It requires matching stopped worker evidence, unchanged approved identity/input, recorded payment, no manual hold, and owner authorization. Old run/bridge files remain unchanged. This command is not automatic replay of uncertain or historical jobs.

Deploy additive `2026_11_02_110000_add_codex_scene_progress.php` only after fresh verified backup; drain existing CLI work before refreshing the dedicated worker. Preserve schema/status/ledger, S3 outputs and original attempts on recovery. Old collectors cannot understand protocol 4; do not roll back to them while new runs exist. No credentials, new AWS resource or external messaging is added.

## Automatic queue — 1 November 2026

Owner authorized automatic generation for existing and future confirmed stories with an approved identity and any actual paid amount, plus a live monitor. `CODEX_SCENES_AUTOMATIC=true` selects eligible stories every scheduled minute; partial/full/without-shipping paid statuses qualify, receipt-review signals do not. Manual holds, prior runs of every status, and stories already in production are excluded. At most50 stories reserve queue positions; two independent story runs dispatch concurrently on the existing server with unchanged resource limits.

Each run retains its own work directory, encrypted snapshot, order id, UUID and identity checksum. Protocol2 requires all those identifiers in each scene metadata record before private S3 persistence. A composite unique active reservation prevents duplicate work on one story while allowing siblings. Codex processes share the existing authenticated account; directory and correlation checks are not a claim of separate OS users per story. No credentials are copied. See official [state configuration](https://learn.chatgpt.com/docs/config-file/config-advanced) and [authentication](https://learn.chatgpt.com/docs/auth).

`/admin/order-automation/codex-scenes` shows status filters/counts, per-story checkout/child, saved scene count, waiting/running duration, completion and order/ZIP links; it refreshes every10seconds. Per-order panels retain live scenes and activity by Automation. Uncertain provider results pause subsequent dispatch until reviewed/stopped; other running work continues. Known output validation failures (dimensions, PNG format, size, duplicate bytes) enter quality_review, retain story ownership and accepted images, and release execution capacity for other stories. They never replay automatically. The UI shows the specific quality reason. Waiting work can stop without provider calls. This release does not automatically deliver previews, record payments, print, ship, or add AWS resources.

Schema migration expands the old global reservation to `(order_id,active_slot)` and makes the system initiator nullable. Restart the dedicated worker only while idle. Preserve private cached config, adding only automatic/concurrency fields. Recovery must first disable automatic enrollment, reconcile all active runs and retain outputs/history; do not restore the old global-slot code while multiple runs exist.

Validation:36 PHPUnit tests/219 assertions on SQLite and isolated MySQL,10 fake-CLI Python tests including two simultaneous distinct stories, browser-poll Node check, PHP8.3 syntax checks and isolated Vite build. Real subscription throughput/concurrency limits remain observation-dependent.

## Historical manual trial


Owner-approved scope: order-page button only, one story at a time on existing EC2. No automatic enrollment, API-key fallback, customer messaging, payment, printing or shipping. Eligibility: confirmed story, linked successful approved identity, checkout actual paid cents > 0 and no other automation owner. A pending payment-review signal is not a payment.

`codex_scene_runs` retains an encrypted immutable prompt/text/reference snapshot and per-scene verified attachment metadata. A nullable unique active slot reserves one run and its whole checkout. Existing Automation ownership/mutation guards apply. The initiating employee and subsequent Automation actions are audited. The existing scheduler stages/imports explicit requests every minute. Thirteen verified private S3 PNGs change the story to `ready_preview` for internal review; text/print PDF still belong to Studio.

The separate unprivileged worker calls pinned official Codex CLI 0.166.0 through saved ChatGPT authentication. It supplies the approved identity, complete production brief, target scene and previous scene, and explicitly restricts generation to image-only scenes. The native image generation capability is enabled. It never invokes an image API or reads application credentials. Each scene gets one invocation, a 20-minute cap, and a private diagnostic transcript. Failed/uncertain/interrupted runs do not replay; operator stop acknowledges cancellation and releases the reservation, preserving imported images. Cancellation cannot undo provider work or subscription usage already incurred.

The worker uses workspace-write sandboxing, an isolated Unix account, systemd filesystem/network/resource restrictions (50% CPU, 768MB high/1GB max), and private input/output spool directories. Laravel alone accesses private S3. No static AWS keys. The narrowly pinned AppArmor helper profile permits bubblewrap namespaces under Ubuntu 24.04 without disabling global user namespace restrictions or Codex sandboxing. References: [OpenAI permissions](https://learn.chatgpt.com/docs/permissions#how-enforcement-works), [Ubuntu 24.04 restrictions](https://documentation.ubuntu.com/release-notes/24.04/#unprivileged-user-namespace-restrictions).

Deployment requires the runbook procedure, exact additive migration, preserved cached configuration plus only the new `codex_scenes` config, route/view refresh, and graceful refresh of existing workers/FPM for ownership/group membership. `CODEX_SCENES_ENABLED=true` enables the manual UI, not automated order selection. Worker files/service and shared bridge group are reviewed deployment artifacts; inbox is www-data-owned/setgid 2750, outbox worker-owned/setgid 2750. Every published file is 0640. Account auth cache stays 0700 and is never copied from desktop or exposed to Laravel.

Login is user-completed device auth. Never commit/copy auth.json or log credentials. `login status` is a local readiness check; it does not prove the first billed/subscription image request succeeds. CLI image generation, quality, subscription limits, runtime and real 13-scene performance remain unverified until the owner manually starts an eligible story and reviews outputs. A native image at least 1024px high is an internal preview, not a print-resolution certification.

Local verification: synthetic PHPUnit fixtures with all external HTTP blocked, SQLite/PHP8.3 and isolated internal-network MySQL; fake-CLI Python tests for exact count, restart/no-retry, failure, duplicate, cancellation, symlink and credential isolation. Never execute those tests against production.

Recovery: stop new requests by disabling the manual config flag, keep syncing/importing or explicitly stop in-flight work, and preserve the table, snapshots, worker job folders and S3 objects. Stop the dedicated worker only after reconciling active runs; a restart does not retry interrupted generation. Do not drop the table or roll back to code that ignores active ownership while any run remains active. No automatic media or credential cleanup is included.
